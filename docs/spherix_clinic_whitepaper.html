22. Complete Database Entity-Relationship Architecture

The relational schema is modeled in Third Normal Form (3NF) with strict foreign key constraints across appointments, beds, prescriptions, and financial ledgers.

Figure 22.1: Relational Schema & Foreign Key Constraints USERS (id PK, email UK, password_hash, role, blood_group, created_at)
├── DOCTORS (id PK, user_id FK, license_number UK, specialty, consultation_fee)
├── APPOINTMENTS (id PK, patient_id FK, doctor_id FK, scheduled_time, status, token_no)
│   └── PRESCRIPTIONS (id PK, appointment_id FK, clinical_notes, issued_at)
│       └── PRESCRIPTION_ITEMS (id PK, rx_id FK, drug_name, dosage, frequency)
├── ORDERS (id PK, user_id FK, total_amount, payment_status, shipping_address)
├── HOSPITALS (id PK, name, city, country_code, total_beds, icu_beds)
│   ├── BEDS (id PK, hospital_id FK, ward_type, bed_number, status, tariff)
│   └── BLOOD_INVENTORY (id PK, hospital_id FK, blood_group, units_available)
└── AUDIT_LOGS (id PK, actor_id FK, action_type, ip_address, timestamp)

Supports both lightweight SQLite (for edge development) and Microsoft Azure SQL Server / PostgreSQL (for enterprise scaling).
